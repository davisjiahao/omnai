# Architecture Evolution

Use for module boundaries, decomposition, framework replacement, and structural refactoring whose value is broader than one feature.

## Route

```text
code archaeology → boundary model → alternatives → adversarial design review → reversible increments → characterization and operational verification
```

## Gates

- Current seams and coupling are evidenced before redesign.
- Alternatives and trade-offs are documented.
- Non-trivial architectural claims receive a fresh-context challenge.
- Work is sliced so the system stays releasable.
- Compatibility bridges include explicit retirement conditions.

## Evidence

Use characterization tests, architecture review findings, integration checks, and performance or operability evidence relevant to the reason for the change.
