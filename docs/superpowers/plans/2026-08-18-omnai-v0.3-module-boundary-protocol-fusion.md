# OmnAI v0.3 Module-Boundary Protocol Fusion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` task by task. Use `superpowers:test-driven-development` for every behavior change and `superpowers:verification-before-completion` before claiming success.

**Goal:** Integrate Matt-style module/interface/seam/depth/locality/deletion-test reasoning into OmnAI's existing phase protocols while preserving Superpowers-style execution discipline and deterministic Core authority.

**Architecture:** Add no amendment-specific Host, capability, scenario, task, review, or execution schema. Put one conditional module-boundary assessment across existing repository protocols, expose it through existing scaffolds and prepared-stage output contracts, route precise internal-architecture phrases to the existing `architecture-governance` scenario, and enforce review through the existing `architecture` lens.

**Tech Stack:** Markdown Protocol Resources, TypeScript, Node test runner, YAML run manifests.

**Design authority:** `../specs/2026-08-18-omnai-v0.3-module-boundary-protocol-fusion-design.md`

## Global constraints

- Add no Host Skill, `Capability`, protocol ID, scenario, readiness key, review lens, task field, execution state, or persisted `ModuleAssessment` beyond changes separately approved in the v0.3 execution plan.
- Keep domain ownership in `domain.md`, external producer/consumer boundaries in `contract.md`, and target internal shape in `design.md`.
- Keep `interaction.brainstorm` as the alternative-comparison interaction.
- Preserve deterministic Core authority and immutable v0.3 `ContractSnapshot`/`RunPacket` semantics.
- Make small stable-interface changes explicitly eligible for `not-applicable`; do not force ports or adapters.
- Preserve the unrelated Milestone C execution files already committed at base `62dd8fd`.
