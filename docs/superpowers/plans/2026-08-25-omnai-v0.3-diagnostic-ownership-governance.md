# Omnai v0.3 诊断归属与原生编译面治理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不修改旧 Execution 引擎、不恢复兼容读者的前提下，为当前 888/76 TypeScript RED 建立可执行的跨计划归属门，并最迟在 Plan07 把原生编译面恢复为全绿。

**Architecture:** 原有 Plans02–09 的显式 Files 行继续拥有 22 files/312 diagnostics；本补充只为 54 files/576 diagnostics 增加精确处置。Plan02–06 使用“已完成计划零诊断 + 剩余诊断全部由未来计划拥有”的 transition gate，Plan07 切断 native graph 对 `src/execution/**` 的最后依赖并从原生 tsconfig 排除未修改的 legacy surface，Plan09 删除或迁移剩余顶层 legacy tests 后执行最终全绿认证。

**Tech Stack:** Node.js 20+、TypeScript 5.9、ESM、`node:test`、Git、现有 npm scripts；不新增依赖。

**Spec:** `docs/superpowers/plans/2026-08-23-omnai-v0.3-full-pipeline-fusion.md`、`.superpowers/sdd/2026-08-23-omnai-v0.3-01-native-schema-catalog/final-diagnostic-ownership-amendment.md`

## Global Constraints

- 本文件只窄化替代 master 的“每个中间计划必须 repository-wide GREEN”条款；最终 Plan07–09 的 `npm run typecheck`、`npm run build` 与全量测试仍必须 exit 0。
- Plan02 入口要求 Plan01-local focused gates GREEN、Plan01-owned diagnostics=0、所有剩余 diagnostics 均有本文件或原计划的未来 owner；不把 RED 说成 GREEN。
- 每个 Plan02–06 退出时，已完成计划拥有的路径 diagnostics 必须为 0；未来计划拥有的诊断可以继续存在，但总数、文件与 owner 必须形成 fresh ledger。
- `src/execution/**` 八个诊断文件只能 `EXCLUDE_UNCHANGED`：不得修改、删除、包装、兼容或把新权限语义塞入其中；Plan07 必须通过 native importer 清零和 exact no-diff 证明退休。
- 新测试进入对应模块 `src/**/test/`；顶层 `test/**` 只能由本表 owner 迁移为模块测试或删除，不能继续新增。
- 不修改用户现有十份计划；本补充作为第十一份独立计划提供 superseding scope。
- 不新增 npm 依赖，不发布 WorkflowLock，不 push；所有代码注释详细使用中文，提交信息全中文。
