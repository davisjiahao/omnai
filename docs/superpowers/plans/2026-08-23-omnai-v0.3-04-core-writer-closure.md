# OmnAI v0.3 Core Writer Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 Task 9E 的 Core Change 部分：用 canonical ChangeId + authenticated facade 替换 raw ChangeRef/store 输入，并把 Decision、Flow、Reconcile、Scenario、readiness/metadata/archive 等写入全部映射到已认证 owner。

**Architecture:** Public 调用只接受 `ChangeId` 或只读 `ChangeLocator`；mutation 一律拒绝 ACTIVE/slug/directory/metadata object。无写 native gate 后，Core 解析成非导出的 `ResolvedChangeHandle`，在 exact Change lock 内构造 context。每个 mutation 都通过共享 fence/request/recovery状态机进入一个 owner；不存在 generic machine-root replacement。

**Tech Stack:** TypeScript、Plan 03 authority/project primitives、Zod、Node test runner、static export/writer census。

**Spec:** 主规范第 12–13.7、15.1–15.4、17、19/9E、20.4、20.9 节。

## Global Constraints

- 依赖 Plan 03；Stage/Task/Issue/Evidence/verification writer 由 Plan 05 所有，本计划不临时放宽它们。
- `src/index.ts` 最终 exact allowlist 由 Plan 07 写入；本计划先建立 `src/core/public/index.ts` 的候选 surface。
- 不修改受保护的 `src/core/paths.ts`；canonical path resolution 放入新模块并只消费已验证 Project/Change inventory。
- 所有 mutation 返回 committed authority head；不返回 directoryName、raw mutable target、provider binding 或 store capability。
- 每个 public writer 的无 key、同 key 不同 digest、completed response-loss、stale completed retry 和 pending-owner conflict 都必须覆盖。
