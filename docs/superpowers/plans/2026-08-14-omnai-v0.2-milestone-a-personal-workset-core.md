# OmnAI v0.2 Milestone A — Personal Workset Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the CLI-only v0.2 vertical slice that lets one engineer register multiple repositories, create a Workset, research candidates read-only, promote confirmed write targets into isolated Git worktrees, and generate a multi-root VS Code `.code-workspace` without a server, database, daemon, or LLM call from OmnAI Core.

**Architecture:** Keep all project-level engineering truth in each repository's existing `.omnai/` state. Add a separate user-local workspace module under `src/workspace/` for Project Registry, Workset manifests, Git worktree lifecycle, and generated VS Code workspace files. All public functions accept an explicit OmnAI home path so tests are isolated; CLI commands resolve the home from `OMNAI_HOME` or `~/.omnai`.

**Tech Stack:** Node.js 20+, TypeScript, Commander, Zod, YAML/JSON, Node `fs/path/os/child_process`, native Git CLI, existing `node:test` harness.

## Global Constraints

- v0.1 repository-local `.omnai/` remains authoritative for Change, Revision, Baseline, artifacts, tasks, evidence, review, and learning.
- No Web UI, Webview, Fastify/Express/Spring Boot, SQLite/PostgreSQL, daemon, vector database, or built-in LLM API.
- Original registered repositories are read-only execution sources; source-code writes for an active Workset member must happen in a dedicated Workset Git worktree.
- A candidate project does not receive a worktree until research confirms modification is required.
- Workset member lifecycle is `CANDIDATE -> RESEARCH_ONLY -> ACTIVE | OBSERVED_ONLY`; `ACTIVE -> INACTIVE` retains the worktree until later explicit cleanup.
- Generated `.code-workspace` contains active writable Workset worktrees only and is regenerable from Workset state.
- Milestone A does not implement parallel Waves, Run claims, selective re-entry, Grill/Brainstorm routing, or the VS Code extension; those belong to later milestones.
- New behavior is implemented test-first using RED -> GREEN -> REFACTOR.
