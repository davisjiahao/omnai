# OmnAI v0.3 RecoveryAuthorityPlan 统一恢复权限 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 ordinary Reconcile、Decision Reconcile 与 Flow assessment 建立同一个 prepare-before-write、精确前缀、完整审计候选集和不可变提交协议，关闭 AR-A Task 5 round-2 遗留的 source/target/completed 与 selector 绕过。

**Architecture:** 新增纯 `RecoveryAuthorityPlan` 内核、单次只读 snapshot loader 与确定性 owned-Reconcile target builder；三个 consumer adapter 从冻结 transaction 和同一 snapshot 生成唯一有序操作。事务路径通过 `OWNED_TRANSACTION` 提交不可变 plan，无事务内部路径通过 `UNOWNED_INTERNAL` 保留现有行为；completed 与全局 lineage 复用同一 audit descriptor 和最终边界规则。

**Tech Stack:** TypeScript 5.9、Node.js 24、Zod 4、`node:test`、YAML/JSONL 本地持久化、`diagnostics_channel` crash seam。

**Spec:** `docs/superpowers/specs/2026-08-25-omnai-v0.3-recovery-authority-plan-design.md`

- `RecoveryAuthorityOperation` 只是现有 writer 的进程内描述；不新增持久事件格式或最终 `AuthorityRecordV1`。
- owner 只来自已认证 transaction；candidate-set 先按 Change、target Revision、owned event kind 形成，再检查 correlation、Decision ID、from/to、baseline、timestamp、detail 与 data。

```ts
export function selectRecoveryAuditCandidates(
  events: readonly ProgressEvent[],
  owner: RecoveryAuthorityOwner,
  audit: RecoveryAuditContract,
): Array<{ readonly event: ProgressEvent; readonly index: number }> {
  const kinds = new Set(audit.ownedEventKinds);
  const stable = events.map((event, index) => ({ event, index })).filter(({ event }) => (
    event.changeId === owner.changeId
    && event.revision === owner.targetRevision
    && kinds.has(event.event)
  ));
  const boundaries = stable.filter(({ event }) => event.event === audit.finalBoundaryKind);
  if (boundaries.length > 1) throw recoveryDrift('RECOVERY_AUDIT_BOUNDARY_MISMATCH');
  const boundaryIndex = boundaries[0]?.index ?? Number.POSITIVE_INFINITY;
  return stable.filter(({ index }) => index <= boundaryIndex);
}

function resolveDurablePrefix(
  source: RecoveryMachineProjection,
  observed: RecoveryMachineProjection,
  operations: readonly RecoveryAuthorityOperation[],
  conflictDetail: string,
): number {
  const projections = [cloneProjection(source)];
  for (const operation of operations) {
    projections.push(applyOperationToProjection(projections.at(-1)!, operation));
  }
  const matching = projections.map((projection, index) => ({ projection, index }))
    .filter(({ projection }) => projectionEquals(projection, observed));
  if (matching.length !== 1) throw recoveryDrift(conflictDetail);
  return matching[0]!.index;
}
```

`applyOperationToProjection()` 对 write/ensure 覆盖 `files[path]`，对 `APPEND_AUDIT` 只追加 owned audit；同一路径重复写自然产生不同 prefix。返回对象、数组和 expected values 全部 clone 后 freeze。

```ts
export function deterministicRecoverySignalId(owner: RecoveryAuthorityOwner): string {
  const epoch = Date.parse(owner.createdAt);
  if (!Number.isSafeInteger(epoch)) throw new AuthorityError(
    'AUTHORITY_INVALID_INPUT', 'RECOVERY_AUTHORITY_OWNER_INVALID',
  );
  const suffix = createHash('sha256')
    .update(`${owner.transactionKind}\0${owner.changeId}\0${owner.correlationId}`, 'utf8')
    .digest('hex').slice(0, 8);
  return `SIG-${epoch}-${suffix}`;
}
```

async function files(root, suffix) {

## 完成定义

- 所有带 PENDING owner 的首次目标写入前都已持有同一 `RecoveryAuthorityPlan`。
- current machine state 对唯一 operation sequence 只有一个精确 prefix；archive 缺失与后序 durable 不可被补写掩盖。

- package/CLI 保持 `0.2.0`，未修改 public exports/lockfile/dependencies，未生成 WorkflowLock，未启用 micro-change，未 publish/push。
