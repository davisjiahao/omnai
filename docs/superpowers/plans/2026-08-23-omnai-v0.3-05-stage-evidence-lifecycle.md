# OmnAI v0.3 Stage and Evidence Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 Task 9E 的 Stage 生命周期：让 Prepare/Run/Task/Issue/Evidence/Verification/Complete 全部由锁定 catalog 编译、Run 绑定和全局权限链驱动，并实现 repository retry lineage。

**Architecture:** `prepareStage` 冻结 `RunAuthorityContractV3`、source machine state、repository basis/subject 和唯一 authored-output 路径；Run descendant 只能按 catalog 允许的 owner/binding/count/ordinal追加。Plan/Review/QA/Canary 是 authored draft 后由 Core 严格导入；Task/Issue 是 typed action；Verify 使用两阶段 command ticket和 Task-set CAS。`completeStage` 以原 prepare head为外部 fence，内部认证完整 descendant suffix。

**Tech Stack:** TypeScript、authority compilers、Git provider、frozen bytes、Node command runner、Zod、Node test runner。

**Spec:** 主规范第 7.2.2–7.2.3、12.5、13.6–13.7、15.3 Stage/Evidence API、17、19/9E、20.4、20.9、21 节。

## Global Constraints

- 依赖 Plan 04；每个 Run/receipt 是全局链 top-level owner，不另建 per-Run 权限链。
- Caller 不提供 protocolRoot/catalog/compiler/target TaskFile/target IssueState/ordinal/EvidenceId/time/output destination/subject/status fold。
- `prepareStage`: work 必须 taskId，review 可选 taskId，其余禁止；retryRunId 只允许 work/simplify。
- `completeStage`: PLAN_STAGE 必须 expectedTasksHash，其他 terminal 禁止；调用者传原 prepareAuthorityHead，不传最后 descendant head。
- negative Evidence 持久化一次并把 Run 置 `EVIDENCE_FAILED/CONCERNS`；原 Run 不得继续追加或完成。
- Work/Simplify root basis never moves across retry；RepositoryWorkBasis 保持 provider-free exact five keys。
