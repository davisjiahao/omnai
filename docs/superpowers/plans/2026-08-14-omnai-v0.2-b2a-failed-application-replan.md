# OmnAI v0.2 B2a Failed Application Replan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover a DECIDED WRE whose project application failed because its frozen Revision/Baseline precondition drifted, without changing already-applied siblings or discarding audit history.

**Architecture:** Keep the existing WRE and replace only the stale failed project's executable frozen application after explicit confirmation. Preview recalculates the deterministic closure from current Project Change truth without mutation; confirm archives the old failed attempt in `attemptHistory`, freezes the new current precondition, resets the application to PENDING, and then reuses the existing apply/idempotency path.

**Tech Stack:** Node.js 20+, TypeScript, Commander, Zod, YAML/JSONL, native Git CLI, `node:test`.

## Global Constraints

- No Web UI, server, database, daemon, background scheduler, or built-in LLM API.
- Only `FAILED + STALE_PRECONDITION` applications may use this replan flow.
- Preview is read-only and must not mutate WRE, Workset, Project Change, Task, Evidence, Revision, or Baseline state.
- Confirm must recalculate from current repository truth; it must not trust a client-supplied preview as the write contract.
- Existing APPLIED and NOT_REQUIRED sibling applications must remain unchanged.
- The replaced failed frozen attempt must remain durable in `attemptHistory`.
- Existing `<WRE>/<project>` correlation Revision lineage blocks replan.
- Replan itself never advances a Project Change Revision/Baseline; only the existing `applyWorksetReentry()` path may do so.
- The WRE remains DECIDED after confirm and becomes RESOLVED only through existing apply/finalize semantics.
