# OmnAI v0.2 B2b User-level Host Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide one canonical four-Skill OmnAI integration for local Codex, Claude Code, and OpenCode, with deterministic context discovery and safe user-level installation, while deleting the unreleased project-local Host installation model.

**Architecture:** Add a read-only context resolver that prefers Workset markers over Git repository detection. Add a user-host module that installs exactly four packaged Skill files into each Host's native user directory and records ownership/integrity in `~/.omnai/hosts/<host>.yaml`. Keep natural-language reasoning in the Host Skills and every workflow/state transition in existing OmnAI Core/CLI.

**Tech Stack:** Node.js 20+, TypeScript, Commander, Zod, YAML, SHA-256, Node `fs/path/os/crypto`, existing Git/workspace APIs, `node:test`, GitHub Actions Node 20/22 matrix.

## Global Constraints

- Exactly four canonical Skills: `omnai`, `omnai-grill`, `omnai-brainstorm`, `omnai-reconcile`.
- `omnai-run` is absent until Milestone C implements Wave/Claim/Run primitives.
- Canonical Skill content is shared across Claude Code, Codex, and OpenCode; no three-way workflow fork.
- User-level destinations are `~/.claude/skills`, `~/.agents/skills`, and `~/.config/opencode/skills` respectively.
- Every Skill starts with `omnai context --json`; Skills do not independently infer context.
- Workset context outranks repository context because Workset projects are Git worktrees.
- `omnai init` only initializes repository state and has no `--host` option.
- No compatibility layer for the unreleased project-local Host installer or `ProjectConfig.installedHosts`.
- Installer never silently overwrites foreign, missing, or drifted managed Skills.
- `install all` preflights every requested Host before any write.
- No Web UI, server, database, daemon, scheduler, or built-in LLM API.
- Production behavior is implemented test-first with RED -> GREEN -> REFACTOR.

- [ ] **Step 4: Implement minimal context resolver**

Algorithm:

```text
resolve absolute cwd
try discoverExecutionContext(cwd)
  if found:
    resolve Workset from home
    if discovered first segment matches a Workset member:
      return workset-project
    return workset
otherwise try findRepositoryRoot(cwd)
  if no Git root: return none
  if .omnai/config.yaml absent: return repository initialized=false
  load config read-only and return repository initialized=true
```

Do not call `initializeProject()`.
