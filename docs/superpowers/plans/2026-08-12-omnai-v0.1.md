# OmnAI v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a lightweight repository-local TypeScript CLI and native skill pack that supports the complete OmnAI v0.1 adaptive workflow and all fifteen scenario profiles.

**Architecture:** A single dependency-free runtime package stores state under `.omnai/`, loads built-in scenario profiles, computes readiness deterministically, snapshots revisions during reconciliation, validates task DAGs and evidence, and installs thin host skills. Markdown is used for human-facing artifacts; JSON/JSONL are the machine authority.

**Tech Stack:** Node.js 20+, TypeScript 5.x, ESM, Node built-in `parseArgs`, Node built-in test runner through `tsx`, npm.

## Global Constraints

- The runtime package MUST have zero production npm dependencies.
- The CLI MUST NOT call an LLM API or run a background daemon.
- All durable project state MUST remain under `.omnai/`.
- Every file path derived from user input MUST be constrained to the repository root.
- Existing non-OmnAI host skills MUST NOT be overwritten.
- All fifteen scenario profiles and scenario documentation pages MUST ship in v0.1.
- Behavior-changing operations MUST be backed by tests and fresh command output before completion is claimed.
- The implementation MUST remain portable across macOS, Linux, and Windows Node.js environments.

---

### Task 1: Establish the TypeScript package and test harness

Create `package.json`, `tsconfig.json`, `.gitignore`, `src/cli.ts`, `src/index.ts`, and `test/smoke.test.ts`. Use ESM, strict TypeScript, `bin.omnai = dist/cli.js`, `npm run build`, `npm test`, and `npm run check`.

### Task 2: Implement canonical types, repository paths, and atomic file utilities

Create canonical workflow types, safe repository-relative path resolution, JSON/JSONL/Markdown helpers, and atomic writes. Test slug normalization and path traversal rejection.

### Task 3: Build the complete scenario profile registry

Ship profiles for `code-query`, `bug-fix`, `small-feature`, `complex-domain-feature`, `cross-service-change`, `migration-program`, `product-discovery`, `ui-ux-feature`, `performance-investigation`, `architecture-governance`, `data-migration`, `shared-library`, `emergency-hotfix`, `incident-response`, and `release-failure`. Each profile must declare purpose, signals, required/optional/skipped stages, risk, approvals, evidence, and route.

### Task 4: Implement project initialization and change scaffolding

Implement idempotent `init`, `new`, `list`, and `use`. A new change creates all canonical artifacts, initial readiness, `REV-001`, task storage, evidence, and decisions directories.

### Task 5: Implement readiness routing, status, and next-step recommendations

Implement deterministic `status` and `next` behavior based on scenario profile, readiness, reconcile state, and task frontier. Never recommend a skipped stage.

### Task 6: Implement task DAG validation and event ledger

Add dependency validation, cycle detection, frontier calculation, state transition validation, and append-only progress events.

### Task 7: Implement revision snapshots and selective reconciliation

Support L0-L5 reconcile levels, immutable pre-change revision snapshots, downstream readiness invalidation, task impact states, and next-stage recommendations.

### Task 8: Implement repository validation

Validate project/change files, schemas, scenarios, readiness, revisions, task cycles, evidence, archive readiness, and unresolved placeholders. Emit stable diagnostic codes.

### Task 9: Implement all native host skills and installers

Write original OmnAI-native skills for start, frame, research, model, map, spec, design, plan, work, debug, verify, QA, ship, learn, and reconcile. Add safe project/user installers for Claude Code, Codex, and OpenCode layouts.

### Task 10: Wire the complete CLI and help output

Expose `init`, `new`, `list`, `use`, `status`, `next`, `scenario list/show`, `event`, `reconcile`, `validate`, and `install-skills`. Support `--repo`, `--json`, stable errors, and exit codes.

### Task 11: Write every scenario expansion page and workflow reference

Create one complete documentation page per scenario. Every page must contain `When to use`, `Route`, `Artifacts`, `Human gates`, `Evidence`, `Reconciliation`, and `Example`. Add shared references for the four facts, readiness vector, task DAG, context packets, evidence ledger, revisions, and knowledge promotion.

### Task 12: Add the Java authorization migration example

Add a valid example showing current-state research, Authorization/AuthorizationUsage semantic separation, delta spec, design, task DAG, progress, evidence, and an L3 reconciliation revision.

### Task 13: Finish README, CI, package verification, and release evidence

Complete installation and end-to-end documentation, architecture guide, MIT license, changelog, CI, and final package verification with `npm run check && npm pack --dry-run`.

## Required verification

Every task follows red/green testing. The final branch must pass:

```bash
npm install
npm run check
npm pack --dry-run
git diff --check
```

The repository must contain all fifteen profiles, all fifteen scenario pages, all fifteen native skills, and the Java migration golden example before the implementation is considered complete.
