# OmnAI v0.2 B2a Project Reconcile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bind each writable Workset project to exactly one Project Change, freeze user-approved per-project Reconcile plans, and apply those plans deterministically through repository-local Revision/Baseline reconciliation.

**Architecture:** Keep Workset coordination in `src/workspace/`, keep repository truth in existing `src/core/` modules, and add a small deterministic planning layer between them. Agent hosts propose `reopenFrom` and task roots; Core derives scenario-specific readiness closure and Task-DAG closure, freezes them at DECIDED, and applies them idempotently.

**Tech Stack:** Node.js 20+, TypeScript, Commander, Zod, YAML/JSONL, native Git CLI, `node:test`.

## Global Constraints

- No Web UI, server, database, daemon, background scheduler, or built-in LLM API.
- One Workset member binds to at most one Project Change.
- `activeChange` is suggestion-only and never an automatic binding rule.
- PENDING WREs may not mutate project-local Change state.
- DECIDED WREs freeze `rulesVersion`, revision/baseline preconditions, readiness closure, and task closure.
- RESOLVED means every required project application is APPLIED or NOT_REQUIRED.
- Existing repository-local `reconcileChange()` remains the only Revision/Baseline mutation engine.
- Existing v0.1 callers of `reconcileChange()` keep current behavior when no explicit readiness scope is supplied.
- Evidence files are never deleted; active Revision controls freshness.
