# OmnAI v0.2 Milestone A — Aggregate Execution Workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the generated VS Code multi-root `.code-workspace` model with one ordinary aggregate directory whose direct children are Workset Git worktrees, so VS Code and the main coding-agent session can open that directory directly.

**Architecture:** Keep `workset.yaml` as authoritative personal coordination state. Add a lightweight marker inside `worksets/<id>/workspace/` for context discovery; create each confirmed writable project as a real Git worktree directly below that aggregate root; retain inactive worktrees in place. Remove `.code-workspace` projection/synchronization entirely and expose the aggregate root through `omnai workset path`.

**Tech Stack:** Node.js 20+, TypeScript, Commander, Zod, YAML/JSON, Node `fs/path/child_process`, native Git CLI, existing `node:test` harness.

## Global Constraints

- `docs/design/omnai-v0.2-aggregate-execution-workspace.md` supersedes every `.code-workspace` / multi-root requirement in the earlier v0.2 design and Milestone A plan.
- Project-local `.omnai/` remains authoritative for Change, Revision, Baseline, artifacts, tasks, evidence, review, and learning.
- Original registered repositories remain read-only execution sources; Workset source writes happen only in dedicated Git worktrees.
- `CANDIDATE`, `RESEARCH_ONLY`, and `OBSERVED_ONLY` projects have no child directory under the aggregate workspace.
- `ACTIVE` projects have one real Git worktree directly under the aggregate workspace.
- `ACTIVE -> INACTIVE` retains the worktree at the same path and makes it non-writable to new Workset Runs.
- No `.code-workspace` file, VS Code multi-root synchronization, Web UI, database, daemon, server, or built-in LLM API.
- New behavior is implemented test-first using RED -> GREEN -> REFACTOR.

- [ ] **Step 1: Write failing marker/context tests**

```ts
import assert from 'node:assert/strict';
import { test } from 'node:test';
import { join } from 'node:path';
import { pathExists, readYaml } from '../src/core/files.js';
import { createTestDirectory } from './helpers.js';
import { createWorkset } from '../src/workspace/worksets.js';
import { discoverExecutionContext, ensureExecutionWorkspace } from '../src/workspace/execution-workspace.js';
import { worksetMarkerPath, worksetWorkspaceRoot } from '../src/workspace/paths.js';

test('creates one aggregate root with a Workset pointer marker', async () => {
  const home = await createTestDirectory('omnai-home-');
  const workset = await createWorkset(home.root, 'Authorization Migration');
  const root = await ensureExecutionWorkspace(home.root, workset);
  assert.equal(root, worksetWorkspaceRoot(home.root, workset.id));
  assert.equal(await pathExists(worksetMarkerPath(home.root, workset.id)), true);
});

test('discovers Workset scope at aggregate root and project scope below it', async () => {
  const home = await createTestDirectory('omnai-home-');
  const workset = await createWorkset(home.root, 'Authorization Migration');
  const root = await ensureExecutionWorkspace(home.root, workset);
  assert.deepEqual(await discoverExecutionContext(root), {
    worksetId: workset.id,
    workspaceRoot: root,
  });
  assert.deepEqual(await discoverExecutionContext(join(root, 'user-center', 'src')), {
    worksetId: workset.id,
    workspaceRoot: root,
    project: 'user-center',
  });
});
```

## Plan Self-Review

- **Spec coverage:** marker/context discovery, aggregate root, direct child worktrees, staged candidate activation, retained inactive worktrees, no multi-root projection, `workset path`, public exports, and agent cwd behavior all map to explicit tasks.
- **Scope:** Grill/Brainstorm selective re-entry, Waves/Runs/claims, parallel execution, and the VS Code visualization extension remain Milestones B–D and are not pulled into this migration.
- **Type consistency:** Workset IDs remain `WKS-\d{4}`; aggregate root remains `worksets/<id>/workspace`; project child names use registered aliases; member statuses remain the existing shared Zod schema.
- **Safety:** no task resets, cleans, checks out, moves, or deletes the user's original repository or retained inactive worktree.
- **Recovery:** exact expected Workset worktrees are reusable after partial activation persistence failure; unrelated directories/branches stay hard failures.
