# New Product or Product Direction

Use when the problem, user, or product wedge is not yet settled.

## Route

```text
demand reality → status quo → narrowest wedge → success signal → product spec → design → build → browser QA → release → product pulse
```

## Gates

- The target user and painful current behavior are concrete.
- The proposal is challenged as a possible solution, not accepted as the problem.
- The first release is the smallest wedge capable of producing learning.
- Success and failure signals are measurable before implementation.
- Product feedback can trigger a new change or a revision without rewriting history.

## Evidence

Use user or market evidence, acceptance behavior, browser QA, release health, and a post-release product pulse rather than code volume as the measure of success.
